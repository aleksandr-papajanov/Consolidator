# Выбрать и написать полезные тесты

Применять только по явному запросу написать/дополнить тесты или вызову skill.

1. Прочитать [AGENTS.md](../../../AGENTS.md), документы затронутых scope по его
   маршруту и [Testing](../../../Docs/Aspects/Testing.md). Установить требуемое
   поведение по запросу и контрактам, затем прочитать production path и соседние
   tests/fixtures. Git использовать только в пределах текущего разрешения.
2. Для каждого кандидата сформулировать реальную регрессию, которую он поймает:
   Given — состояние и вход, When — публичная операция, Then — наблюдаемый результат.
   Сопоставить с имеющимся покрытием. Оставить сценарий, только если он закрывает
   существенный пробел или новую критичную границу.
3. Выбрать самый узкий существующий уровень из Testing, который доказывает весь
   контракт. Не дублировать один факт на нескольких уровнях; при необходимости
   integration отдельно определить, какую marshaling/export границу он доказывает.
4. Написать небольшой набор цельных use cases через production seams и существующие
   fixtures. Выбрать крайние случаи по рискам этой правки, не по числу веток кода.
   Например, group edit → одна история → Undo/Redo или rejected batch без частичного
   commit полезнее набора проверок отдельных setters.
5. Прочитать test и production path вместе: сценарий должен ловить указанную
   регрессию, допуская рефакторинг с сохранением контракта. Установленные ошибки
   исправлять в их владельце по общим правилам; неверную реализацию не превращать
   в ожидаемое поведение. При failure исследовать причину до изменения assertions.
6. Если запуск разрешён, выполнить относящиеся к задаче проверки по Testing и
   разобрать результаты. Запрос написать tests сам по себе не разрешает build,
   publish или запуск. Иначе закончить код и явно указать отсутствие выполнения.

Сообщить покрытые риски, выбранный уровень, файлы, исправленные ошибки и фактические
результаты. Допустимый scope, ограничения DSP и устройство тестовых проектов
определены в Testing; здесь не создавать второй набор этих правил.

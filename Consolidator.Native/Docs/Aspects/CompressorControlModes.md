# Управление четырьмя компрессорами

CLA-76, CLA-3A, CLA-2A и SSLChannel имеют один Native алгоритм на устройство и
два явно выбранных режима управления. `CompressorControlMode::Normal` включён
по умолчанию. `Emulation` выбирается только конструктором Native-процессора;
нынешние VST3 его не включают и не показывают переключатель. Режим неизменяемый
на протяжении жизни экземпляра, его нельзя автоматизировать.

## Обычный режим

| Контрол | Диапазон | Поведение |
| --- | --- | --- |
| Reduction | 0…1, default 0.5 | Порог `12 - 60*Reduction` дБ; ноль прекращает новую компрессию |
| Output | Native: номинальная амплитуда; VST3: −24…+24 дБ, default 0 дБ | Прямое усиление без референсного taper; автоматический makeup работает отдельно |
| Attack, где есть | 0…1 | От короткой атаки к длинной |
| Release, где есть | 0…1 | От короткого восстановления к длинному |
| Ratio, где есть | 0…1 | От минимального ratio к максимальному |

Reduction задаёт чувствительность, а не гарантированное число дБ ослабления:
фактическая компрессия зависит от входного сигнала, knee, ratio и памяти модели.
Output 0 дБ означает множитель 1; Native амплитуда 0 может использоваться для mute.
При Reduction=0 ранее накопленная память восстанавливается обычным release.
Окраска модели остаётся активной; это не Bypass.

Простые законы заменяют только управление. В CLA-2A/3A не выполняются региональные
или полиномиальные законы Peak Reduction/Gain. CLA-76 не масштабирует аудио
референсным Input и не применяет референсные выходные калибровки или ALL offset. Его базовый
порог линейный, поверх него сохраняются существующие небольшие ALL зависимости
от Attack/Release/Ratio. Все четыре Normal-модели используют компенсацию,
подобранную по музыкальным источникам. Прежний Ratio/Threshold makeup
сохранён только в Emulation. В Normal используется линейно заданный порог; зависимость
формы кривой от референсного Threshold остаётся выключенной.
Исходные детекторы, knee, оптические/ALL памяти и фильтры сохраняются.

### Координаты времени и ratio

- CLA-76: внутренний reference coordinate `7 - 6*value` для Attack/Release;
  прежние функции времени сохранены. Defaults Attack=2/3, Release=0.5.
  Ratio 0…1 в Normal начинается с 1:1. Общая номинальная координата
  `p=3*value/(64-61*value)`, `R=1+99*p` совпадает с SSL;
  default 4:1 при `value=0.4`. Ниже 4:1
  slope=`1-1/R`, ALL amount=0; выше морфирование 4:1 → ALL использует
  `allAmount=(R-4)/96`. Верхний участок — координата морфа, не измеренное
  физическое отношение 4…100:1. Emulation сохраняет прежние 4:1 → ALL.
- SSL: физический Ratio=`1 + 99*3*value/(64-61*value)`; Release повторяет
  референсную шкалу кусочно-линейной функцией: позиции
  0/0.2/0.35/0.5/0.65/0.8/1 соответствуют 0.1/0.15/0.2/0.4/1/2/4 секундам.
  Defaults Ratio=0.4 (4:1), Release=0.5 (0.4 с). Attack=0 соответствует Fast
  1.1 мс, Attack=1 — Normal 43 мс, default 1. Attack в SSL двухпозиционный: значения ниже 0.5 выбирают Fast, остальные Normal.
  Исходные законы обоих концов сохранены; в едином UI доступно только 0 или 1.

## Normal automatic makeup

Компенсация подобрана по восьми оригинальным записям с одинаковым весом источников.
Она приближает среднюю громкость разных алгоритмов при одинаковых настройках;
прежняя калибровка по синусу −18 dBFS удалена. Output остаётся независимым.
Эмуляционные алгоритмы и их референсные законы усиления не изменены.

Формулы, измерения и ограничения: [Program makeup](ProgramMakeup.md).
Статическая компенсация — функция настроек, без измерителя громкости в realtime.
Расчёт выполняется при изменении соответствующих контролов; подготовленный gain
применяется после компрессии и не входит в детектор. CLA-2A/3A зависят только от
Reduction; CLA-76/SSL учитывают также Attack, Release и Ratio.

В универсальном `DeviceCompressor` после статической компенсации работает общая
[адаптивная поправка](AdaptiveCompressorGain.md) по измеренной энергии dry/wet.
Auto Gain по умолчанию включён и управляет единственным видимым Output −24…+24 дБ.
Отдельный предел ±3 дБ удалён; выключение сохраняет достигнутый Output.
## Режим эмуляции в коде

Каждый `*Controls` содержит обычные поля и вложенный `emulation` с референсными
контролами. Единственный `SetControls(const *Controls&)` читает только поля
выбранного режима. Референсные defaults и законы остаются в Native:

| Устройство | Поля `emulation` |
| --- | --- |
| CLA-76 | Input/Output nominal amplitudes, Attack/Release 1…7, Ratio 0…1 |
| CLA-3A | Gain/Peak Reduction normalized 0…1, reference display 0…10 |
| CLA-2A | Gain/Peak Reduction normalized 0…1, nonlinear reference display 0…100 |
| SSL | Ratio 1…100, Release seconds, Fast Attack bool, Threshold dBu |

Пример для будущего исследования:

```cpp
Cla2aProcessor processor(CompressorControlMode::Emulation);
Cla2aControls controls;
controls.emulation.gain = 0.535;
controls.emulation.peakReduction = 0.598;
processor.SetControls(controls);
```

Это запрошенный самостоятельный режим, без миграции старых presets, aliases или
копии аудиоалгоритма. Единый VST3 IDs: algorithm/reduction/output/attack/release/ratio/bypass.
[DeviceCompressor](DeviceCompressor.md)
выбирает один из четырёх алгоритмов; у 2A/3A timing/ratio неактивны. Для обновлённого интерфейса нужны свежие
экземпляры. Нормализованные времена и ratio относятся к управлению; они не
являются секундными или ratio readouts референса.

## Границы проверки

Изменение обычного режима намеренно меняет референсные положения ручек и уровни.
Старые измерения точности относятся к режиму эмуляции, а не к новым defaults.
Source review и сборка не подтверждают точность аудио против референса.
DSP-автотесты запрещены [правилами](../Rules.md); отдельный подбор не выполняется
без запроса на исследование.

Историческая проверка до объединения: Native Release|x64 и четыре Release VST3 были собраны и установлены.
EmulationLab `plugin describe` на установленных VST3 подтвердил Reduction=0.5,
Output=0 дБ и отсутствие референсных Input/Gain/Peak Reduction/Threshold в UI.
У CLA-76 прочитаны Attack=0.6666667, Release=0.5, Ratio=0; у SSL — Attack=1,
Release=0.0769231, Ratio=0. Проверен source-путь controls → ramps → cached
coefficients → audio output, включая Reset и неактивные референсные поля.
Новых аудиорендеров, тестов DSP и CPU benchmark не выполнялось.

# Компенсация громкости по музыкальным источникам

## Цель и область действия

В Normal подобрать похожую громкость четырёх алгоритмов на одной и той же записи
при одинаковых Reduction/Output и доступных Attack/Release/Ratio. Это среднее
согласование алгоритмов, а не обещание одинаковой громкости dry/wet на каждом
сигнале. Emulation сохраняет оригинальные законы усиления.

Старая калибровка по установившемуся синусу −18 dBFS хорошо компенсировала этот
синус, но плохо переносилась на музыку: детекторы и история оптического заряда
ослабляют ударные и плотные записи по-разному. Её коэффициенты и helper удалены.

## Материал и метод

Восемь пользовательских файлов acoustic, bass, electric-hard, electric-soft,
kick, overheads, snare, vocal сохранены без нормализации в
[RawAudio](../../../EmulationLab/Docs/Aspects/RawAudio.md#источники-для-компенсации-компрессоров).
Каждая запись — stereo PCM24 / 44.1 kHz, 12.738 секунды. Рендер: block 128,
новый экземпляр и пустая история для каждого условия, float32 без ограничения
пиков. Уровень Output −24 дБ снимается перед измерением, включая loudness gate.

Метрика — integrated K-weighted loudness с окнами 400 мс, шагом 100 мс,
absolute gate −70 LUFS и relative gate −10 LU, по
[ITU BS.1770](https://www.itu.int/rec/R-REC-BS.1770/en).
RMS и sample peak измеряются отдельно. Offline измеритель не является
сертифицированным loudness meter и не включён в DSP/runtime.

Подбирается среднее ослабление в дБ: сначала измеряется каждый источник,
затем восемь результатов усредняются с одинаковым весом. Тихий kick имеет тот же
вес, что громкий vocal. Записи не складываются в общий поток и не нормализуются.

Первичная сетка: Reduction 0/.2/.35/.5/.65/.8/1; у 76/SSL Ratio
0/.2/.4/.7/1, центр и четыре угла Attack/Release. У 2A/3A игнорируемые
настройки не дублируются. Всего 364 условия на каждом источнике.
Дополнительный подбор около 1:1 использует Ratio .05/.1, Reduction .5/.8/1,
центр и два противоположных угла времени.

## Результат ручного исследования

После выбора формул выполнены новые рендеры готового VST3: шесть дополнительных
сочетаний Reduction/Attack/Release/Ratio на каждом из восьми источников,
четыре алгоритма — 192 WAV, 48 сравнений. Эти сочетания не входят в сетку подбора;
источники те же, поэтому это проверка переноса между настройками, не между записями.
Разброс — разница LUFS между самым громким и самым тихим алгоритмом на одном
источнике и одном наборе контролов. Output у всех одинаковый.

| Разброс между четырьмя алгоритмами, дБ | Прежний закон, оценка | Новая версия, измерение |
| --- | --- | --- |
| Средний | 2.84 | 1.61 |
| Медиана | 2.12 | 1.40 |
| 90-й процентиль | 5.79 | 3.17 |
| Максимум | 10.85 | 5.72 |

Прежняя колонка реконструирует прежний статический gain на том же обработанном
сигнале; обе колонки используют уже исправленную шкалу SSL Release. Это сравнение
законов компенсации, не двух полных исторических сборок. Разница startup ramps
не реконструируется. Новая колонка непосредственно измерена по финальным WAV.

На первичной сетке для активных Reduction≥.5 и Ratio>0 (640 сравнений)
расчётный средний разброс уменьшился с 3.18 до 1.71 дБ, 90-й процентиль —
с 6.56 до 3.34 дБ. Максимум остаётся 10.54 дБ в крайних сочетаниях. Точность
подбора среднего по источникам нельзя путать с ошибкой отдельной записи:
RMS ошибки формулы среднего ослабления составляет около .27/.06/.04/.26 дБ
для 76/3A/2A/SSL соответственно.

## Функция и realtime

У каждой модели свой private `CalculateMakeupGain` в её .cpp. Независимого
CompressorMakeup API нет. Общая математическая форма закона:

```text
x = max(Reduction - onset, 0)
makeupDb = slope * x*x/(x + width)
makeupGain = 10^(makeupDb/20)
```

У оптических алгоритмов onset/width/slope постоянны. У 76/SSL короткие
аналитические поверхности описывают зависимость onset и slope от Ratio и
времени. Коэффициенты описывают среднее этих записей, не внутреннюю электрическую
схему референса. Таблиц опорных точек и интерполяции нет.

Расчёт находится в существующем кэше контролов; на установившихся настройках
audio loop применяет готовый gain. Новых аудиопамятей, lookahead, allocation,
locks, I/O или runtime loudness follower нет. Gain не возвращается в детектор,
поэтому формы компрессии и референсный режим остаются прежними.

## Ограничения

Это описание статического закона. Динамического выходного Auto Gain в основном
strip и исследовательском адаптере нет. Output регулируется вручную. Приведённые исследования относятся к более ранним
версиям; они также предшествуют отключению встроенных аудиофильтров
в Normal; формула не перекалибрована для изменённого Normal signal path.

Одна функция настроек не может устранить различия на всех записях: например,
SSL и оптические модели значительно меньше ослабляют отдельные удары, чем 76.
При крайних Reduction/Ratio остаточная разница может составлять несколько дБ.
На другом входном уровне и другой истории результат тоже меняется. Компенсация
не является limiter и не гарантирует сохранение пиков. Прослушивание в этой
работе не выполнялось; исследованы приведённые записи при 44.1 kHz.

## Emulation: ownership and controls

One Native implementation is compiled by Native and the VST3 target.
CLA-76 is not connected to the existing Compressor graph or Managed ABI.
The sound is derived from CLA-76 Bluey/4:1 and ALL, with Analog Off, Trim 0 and
Mix 100%. Input/Output restore the measured reference attenuator functions. Exact reference emulation is not the current goal.

| Control | Range | Default |
| --- | --- | --- |
| Input | nominal amplitude 0..1, displayed -inf..0 dB | -30 dB |
| Output | nominal amplitude 0..1, displayed -inf..0 dB | -18 dB |
| Attack | reference 1..7, slow to fast | 3 |
| Release | reference 1..7, slow to fast | 4 |
| Ratio | 0..1, 4:1 to ALL | 0 |

Cla76EmulationControls owns these defaults. All controls have 10 ms ramps. Emulation uses the reference Attack/Release coordinate directly before smoothing.
Reference coordinate 1 is slow and 7 fast, matching emulation controls.
Ratio morphs endpoint parameters using one detector/history, with no audio crossfade.

VST3 contains five user controls, Bypass, host state/UI and preallocated float/double
buffer conversion. There are no research parameters, tunable DSP coefficients or
coefficient-reading API in the adapter. Display conversion between dB text and amplitude
belongs to the host UI. Cla76Config is immutable Native configuration.
Presets store only the six host controls; restoration requires every current
control to be valid before any is applied. No aliases or migration exist.

## Emulation signal order

Input attenuator -> +30 dB calibration -> compression -> mode output offset ->
one-pole colour -> Output attenuator and +27.2 dB calibration. Input drives both
audio and detector, as before the control simplification. Zero Input/Output mutes.
Compression, colour and Output share one loop.
Colour and Output do not feed the detector. There is no added saturation,
analog noise, oversampling, hold timer, parallel audio branch or final limiter.
Harmonics generated by time-varying compression remain.

## Detector and compression

The linked detector takes the larger absolute selected-channel sample after Input. State P stores squared amplitude. Reduction uses the preceding P; the
current sample then updates P. This is one sample of control delay, not audio lookahead.
For input amplitude x and attack coefficient cA:

- Rising: P += cA*(x*x-P).
- Falling at 4:1: a=sqrt(P); aNext=a+cR*(x-a); P=aNext*aNext.
- Falling at ALL: root=max(0,sqrt(a)-cR*I); aAll=root*root.
- Intermediate Ratio: aNext=lerp(aNormal,aAll,Ratio), then P=aNext*aNext.

I=1.5*sqrt(DbToGain(baseThresholdDb)) is cached. The base threshold contains
the original Attack span; extra Release curve offsets do not alter I.
In Emulation the detector amplitude includes the reference Input gain.
Normal base threshold is -25.7 dB, knee 6 dB, slope 0.75.
ALL base threshold before sensitivity is -25.84 dB, knee 6 dB, slope 0.9,
output offset +0.65 dB and Attack threshold span 0.46*u.
Here u=(referenceAttack-4)/3. Threshold/slope offsets are polynomials of
r=(referenceRelease-4)/3. Their coefficients belong to Cla76Config.
Fast coupling k=Ratio*u*clamp((referenceRelease-5)/2,0,1) adds k dB to the
threshold and 0.020*k to slope. ALL-only contributions vanish at Ratio zero.

The soft knee computes g from detector dB and active threshold. A separate
bounded memory state s accounts for settling on a constant carrier:

~~~text
m = min(g, memoryLimitDb)
s += memoryCoefficient*(m-s)
appliedReduction = g + Ratio*(min(s,m)-m)
~~~

State s starts at zero and remains warm across Ratio changes. Its contribution
cannot keep attenuating a signal below the compression range. At a constant
input s tends to m, retaining the fast curve's steady reduction.

## Continuous control laws

Attack log seconds uses c0+c1*u+c2*abs(u).
Normal, ALL and ALL fast-release carrier curves have separate three-coefficient
laws. Ratio linearly blends endpoint coefficients in log space. Above reference
Release 4, the carrier/base log-time difference adds with amount
Ratio*clamp((referenceRelease-4)/3,0,1). Release log seconds uses a degree-five
polynomial in r. Exponentiation produces positive times for TimeCoefficient.
No time anchors or segment searches remain.

Memory limit/time are positive quadratic log surfaces:
exp(c0+c1*u+c2*r+c3*u*u+c4*u*r+c5*r*r).
Threshold/slope offsets use degree-four polynomials in r. Coefficient arrays
are function coefficients, not interpolation nodes. Exact values live only
in the Native header, not in documentation or VST3 parameter defaults.

## Linear colour

The corrective low shelf and -0.2 dB bell were removed during simplification.
One-pole stage: pole control 14800 Hz, feedthrough 0.652.
For t=tan(pi*f/sampleRate), p=(1-t)/(1+t), coefficients are
b0=feedthrough, b1=1-p-b0, a1=-p. DC gain is unity. Frequency stays below
Nyquist; p is bounded below by 1-2*b0 so high-frequency gain stays nonnegative.
Coefficients and two channel histories are prepared before audio processing.
The CLA-76 VST3 target no longer compiles the unused DspBiquad.cpp.

## Runtime and verification

Coefficient calculations are cached until Attack/Release/Ratio changes.
The detector power at the bottom of the knee is cached; samples below it skip
log10 because their target reduction is zero. Zero applied reduction skips
DbToGain. Compression/mode gains use one channel gain application, and
selected output pointers are gathered once per block. Memory history remains warm.
These reduce identifiable work; no measured CPU percentage is claimed.

## Simplification and final manual comparison

The one-pole colour/Gain now run in the compression loop: one audio pass instead
of four. Two biquads and their state/prepare/reset paths are removed. The tiny
normal-release quartic coefficient and memory-limit cross coefficient become zero;
shared polynomial bases remain because other endpoint coefficients are meaningful.
The attack basis uses abs instead of the smoothed bend square root. Constants are
rounded to useful precision. Bounded ALL memory stays warm and its dynamics remain.
Control polynomials/surfaces are cached; they are not costly per-sample fitting.

Requested EmulationLab renders use nominal Input -30/Output -18 dB, mode endpoints
and Attack/Release 0/0.5/1 (18 cases). The same four-pair 5/4/5-second 998.6 Hz raw
input compares the previous approved candidate, simplified candidate and reference.
Reference remains Bluey, Analog Off, Mix 100%, Trim 0. Native gain controls remain
nominal, so the reference is not an exact level specification.

| Metric, before -> simplified | 4:1 | ALL |
| --- | --- | --- |
| Attack shape RMSE against reference, dB | 0.4944 -> 0.4911 | 1.2630 -> 1.2675 |
| Normalized recovery RMSE | 0.09525 -> 0.09511 | 0.09700 -> 0.09673 |
| Plateau gain RMSE, dB | 0.5266 -> 0.5327 | 0.1815 -> 0.1907 |
| Direct candidate-envelope difference RMSE, dB | 0.0239 | 0.0428 |

Attack uses 32 log-spaced 1 ms peak windows 1..200 ms, relative to each output's
own plateau. Recovery uses 40 normalized windows 10 ms..4 seconds; reference
spans below 1 dB are excluded. Rate is 44.1 kHz. Quiet candidate colour difference
over 60 frequency/rate points from 20 Hz is 0.099 dB RMS, maximum +0.222 dB at 80 Hz.
Colour rates are 44.1/96 kHz. No perceptual equivalence or universal bound is claimed.
These observations are manual investigation, not DSP automated tests.

A bounded timing proposal based on measured-envelope time scaling offered only
0.012 dB normal/0.008 dB ALL approximate attack RMSE improvement. It was not
adopted; it does not warrant further configuration or runtime complexity. The Release
VST3 was built and installed after removing the unused target dependency. Source
review found no new ownership/realtime issues. CPU speedup was not benchmarked.

Process performs no allocation, locking, logging, I/O, offline fitting or Managed
calls. The current VST3 target is ConsolidatorCompressor_VST3. Restart the host after installation.
[DSP rules](../Rules.md) prohibit automated audio tests; manual research requires
an explicit request. Source review and an authorized build do not establish
perceptual equivalence or exact reference matching.

## Code map

- Process reads the control ramps, updates cached coefficients and applies one sample loop.
- UpdateMode morphs 4:1/ALL coefficients and invalidates timing caches.
- UpdateControlCoefficients compiles the effective timing, curve and bounded-memory laws.
- CalculateTargetReductionDb reads the preceding detector state.
- UpdateDetector charges power or releases amplitude; UpdateMemoryReductionDb advances ALL history.
- ProcessColourSample applies the prepared one-pole colour before output gain.

The model is complete. This organization refactor changes source layout and method boundaries;
control ranges, constants, state update order and signal routing are retained.

## Restored reference controls

Input/Output use the previously fitted rational functions, recovered from the
saved conversation before nominal-gain simplification:

~~~text
x = nominal amplitude, t=sqrt(x)
measuredGain = x*P8(t)/(1+t*Q7(t))
~~~

The nine/eight numerator/denominator values in the Native cpp are polynomial
coefficients, not interpolation nodes. Full precision is retained because the
rational evaluation contains cancellation. Horner evaluation and nominal-control
caches preserve the earlier mathematical optimization; curves run only when
controls change. The mapped amplitude targets then ramp over 10 ms.
Default construction prepares the mapped -30/-18 dB targets even without an
initial SetControls call. Reset preserves those targets and clears histories.

Timing/control surfaces, bounded ALL memory and the simplified one-pole colour
are retained. Corrective biquads, extra saturation, tuning controls and interpolation
anchor tables are not restored. Host IDs are input/output/attack/release/ratio/bypass;
use a fresh instance after the range/ID change. Ratio 0 remains the fitted 4:1
endpoint and 1 ALL; intermediate morph positions are not the unmodelled reference
8/12/20 buttons. Restoring controls is not a claim of exact full-band emulation.

## Universal VST3

The individual adapter/target is removed. This Native model is now selected by
[DeviceCompressor](DeviceCompressor.md) in Consolidator Compressor.
Its UI owns the shared Algorithm/Reduction/Output/Attack/Release/Ratio controls.

## Normal automatic makeup

Normal uses a compact settings law fitted to eight unnormalised musical sources,
with equal source weights. It balances average loudness across algorithms rather
than preserving a particular sine operating point. Optical models depend only on
Reduction; 76/SSL also include Attack, Release and Ratio. No running loudness
matcher or new detector history is added. Original Emulation gain is unchanged.
[Method, results and limits](ProgramMakeup.md).

## Normal ratio below 4:1

Normal Ratio now starts at 1:1 with the same nominal position as SSL:
p=3*value/(64-61*value), R=1+99*p; default value=0.4 (4:1). Below 4:1 the compression slope is
1-1/R, using existing 4:1 knee/timing and zero ALL contribution. Above 4:1 the
previous morph amount is (R-4)/96. Makeup uses the resulting active slope.
Emulation controls, default Ratio=0 (4:1), timing and old morph are unchanged.

## Ownership and controls

One Native implementation is compiled by Native and the VST3 target.
CLA-76 is not connected to the existing Compressor graph or Managed ABI.
The sound is derived from CLA-76 Bluey/4:1 and ALL, with Analog Off, Trim 0 and
Mix 100%. Input/Output intentionally use nominal gain rather than measured
hardware attenuator curves. Exact reference emulation is not the current goal.

| Control | Range | Default |
| --- | --- | --- |
| Input | amplitude 0..1, displayed -inf..0 dB | -30 dB |
| Output | amplitude 0..1, displayed -inf..0 dB | -18 dB |
| Attack | 0..1, shortest to longest time | 2/3 |
| Release | 0..1, shortest to longest time | 0.5 |
| Ratio | 0..1, 4:1 to ALL | 0 |

Cla76Controls owns these defaults. All controls have 10 ms ramps. Native maps
Attack/Release to the fitted reference coordinate v=7-6*amount before smoothing.
Reference coordinate 1 is slow and 7 fast; public controls increase with time.
Ratio morphs endpoint parameters using one detector/history, with no audio crossfade.

VST3 contains five user controls, Bypass, host state/UI and preallocated float/double
buffer conversion. There are no research parameters, tunable DSP coefficients or
ReadTuning path in the adapter. Display conversion between dB text and amplitude
belongs to the host UI. Cla76Tuning is immutable Native configuration.
Presets store only the six host controls; restoration requires every current
control to be valid before any is applied. No aliases or migration exist.

## Signal order

Nominal Input gain -> +30 dB input calibration -> compression -> mode output
offset -> low shelf -> bell -> one-pole colour -> nominal Output gain and
+27.18 dB output calibration. Zero Input/Output remains exact mute.
Colour and Output do not feed the detector. There is no added saturation,
analog noise, oversampling, hold timer, parallel audio branch or final limiter.
Harmonics generated by time-varying compression remain.

## Detector and compression

The linked detector takes the larger absolute selected-channel sample after
Input. State P stores squared amplitude. Reduction uses the preceding P; the
current sample then updates P. This is one sample of control delay, not audio lookahead.
For input amplitude x and attack coefficient cA:

- Rising: P += cA*(x*x-P).
- Falling at 4:1: a=sqrt(P); aNext=a+cR*(x-a); P=aNext*aNext.
- Falling at ALL: root=max(0,sqrt(a)-cR*I); aAll=root*root.
- Intermediate Ratio: aNext=lerp(aNormal,aAll,Ratio), then P=aNext*aNext.

I=1.5*sqrt(DbToGain(baseThresholdDb)) is cached. The base threshold contains
the original Attack span; extra Release curve offsets do not alter I.
Normal threshold is -25.7 dB, knee 6 dB, slope 0.75.
ALL base threshold is -25.83700092117243 dB, knee 6 dB, slope 0.902,
output offset +0.65 dB and Attack threshold span 0.45899079779061014*u.
Here u=(referenceAttack-4)/3. Threshold/slope offsets are polynomials of
r=(referenceRelease-4)/3. Their coefficients belong to Cla76Tuning.
Fast coupling k=Ratio*u*clamp((referenceRelease-5)/2,0,1) adds k dB to the
threshold and 0.020*k to slope. ALL-only contributions vanish at Ratio zero.

The soft knee computes g from detector dB and active threshold. A separate
bounded memory state s accounts for settling on a constant carrier:

~~~text
m = min(g, memoryLimitDb)
s += memoryCoefficient*(m-s)
appliedReduction = g + Ratio*(min(s,m)-m)
~~~

State s starts at zero and remains warm across Ratio changes. Its contribution
cannot keep attenuating a signal below the compression range. At a constant
input s tends to m, retaining the fast curve's steady reduction.

## Continuous control laws

Attack log seconds uses c0+c1*u+c2*(sqrt(u*u+0.02*0.02)-0.02).
Normal, ALL and ALL fast-release carrier curves have separate three-coefficient
laws. Ratio linearly blends endpoint coefficients in log space. Above reference
Release 4, the carrier/base log-time difference adds with amount
Ratio*clamp((referenceRelease-4)/3,0,1). Release log seconds uses a degree-five
polynomial in r. Exponentiation produces positive times for TimeCoefficient.
No time anchors or segment searches remain.

Memory limit/time are positive quadratic log surfaces:
exp(c0+c1*u+c2*r+c3*u*u+c4*u*r+c5*r*r).
Threshold/slope offsets use degree-four polynomials in r. Coefficient arrays
are function coefficients, not interpolation nodes. Exact values live only
in the Native header, not in documentation or VST3 parameter defaults.

## Linear colour

Low shelf: 13.698060 Hz, +0.926118 dB, Q 0.707.
Bell: 83.140818 Hz, -0.203248 dB, Q 0.531478.
One-pole stage: pole control 14786.662131 Hz, feedthrough 0.652372409.
For t=tan(pi*f/sampleRate), p=(1-t)/(1+t), coefficients are
b0=feedthrough, b1=1-p-b0, a1=-p. DC gain is unity. Frequency stays below
Nyquist; p is bounded below by 1-2*b0 so high-frequency gain stays nonnegative.
Filter coefficients/storage are prepared before audio processing.

## Runtime and verification

Coefficient calculations are cached until Attack/Release/Ratio changes.
The detector power at the bottom of the knee is cached; samples below it skip
log10 because their target reduction is zero. Zero applied reduction skips
DbToGain. Input/compression/mode gains use one channel gain application, and
selected output pointers are gathered once per block. Memory history remains warm.
These reduce identifiable work; no measured CPU percentage is claimed.

Process performs no allocation, locking, logging, I/O, offline fitting or Managed
calls. VST3 target is ConsolidatorCla76Model_VST3. Restart the host after installation.
[DSP rules](Rules.md) prohibit automated audio tests; manual research requires
an explicit request. Source review and an authorized build do not establish
perceptual equivalence or exact reference matching.
